Механизма два, и работают они независимо: словарь интерфейсных ключей и переводы контента. Дальше разбираем каждый по отдельности.

## Интерфейс

Словарь лежит в базе (`unicore_translations`), а исходные наборы живут в `src/seeds/locales/ru.json` и `en.json`. При старте сервер заливает их с `orIgnore`: существующие значения не перетираются, новые ключи добавляются.

### Добавить ключ

<Steps>
<Step>

### Вписать в оба JSON

```json
{
  "cabinet.new_feature": "Новая штука"
}
```

Состав ключей в `ru` и `en` должен совпадать, иначе на одном из языков будет пусто.

</Step>

<Step>

### Использовать во фронте

```vue
{{ $t('cabinet.new_feature') }}
```

С подстановками:

```vue
{{ $t('cabinet.left_days', { days: 12 }) }}
```

</Step>

<Step>

### Перезапустить сервер

Ключ зальётся в базу при старте и появится в админке.

</Step>
</Steps>

<Callout type="warn" title="`$t()` в Options API">
Списки, собранные через `$t()`, обязаны быть в `computed`. В `data()` они посчитаются один раз при создании компонента и после смены языка останутся на старом.

```js
// ломается
data: () => ({ options: [{ label: this.$t('a.b') }] })

// работает
computed: { options() { return [{ label: this.$t('a.b') }] } }
```
</Callout>

Ключ без перевода отрисовывается сам собой: на глаз заметно сразу, а вёрстку не ломает.

## Контент

Переводы контента лежат в одной таблице с составным первичным ключом:

```
locale_code | entity | entity_id | path | value
```

Порядок колонок выбран так, чтобы ключ работал кластерным индексом: все переводы одной записи оказываются физически рядом, и выборка идёт диапазонным сканом. Дополнительный индекс по `(entity, entity_id)` покрывает выборку по всем языкам сразу.

### Как переводы попадают в ответ

`ContentLocaleInterceptor` работает после сериализации:

1. Читает `x-locale` из запроса. Если заголовка нет или язык совпадает с дефолтным, интерсептор ничего не делает.
2. Обходит ответ вглубь (до шести уровней, с защитой от циклов через `WeakSet`) и собирает объекты, чей класс помечен `@Translatable`.
3. Одним запросом достаёт все нужные переводы.
4. Подменяет поля прямо в объектах ответа.

Заголовок `x-raw-content` выключает подмену. Админка шлёт его, когда ей нужны оригиналы для редактирования.

### Сделать поле переводимым

<Steps>
<Step>

### Пометить сущность

```ts
@Translatable('product', ['name', 'description'])
@Entity({ name: 'unicore_products' })
export class Product { }
```

В первом аргументе задаётся короткое имя типа, оно уедет в базу, во втором — список путей. Звёздочка `*` в пути означает индекс массива:

```ts
@Translatable('server', ['name', 'slogan', 'table.*.title'])
```

</Step>

<Step>

### Описать поля для админки

`workspaces/admin/constants/translatable.ts`:

```ts
product: [
  { path: 'name', label: 'admin.name', type: 'text' },
  { path: 'description', label: 'admin.description', type: 'html' },
],
```

`type` определяет редактор: однострочный, многострочный или WYSIWYG.

</Step>

<Step>

### Подключить в форме

На страницу админки добавляются панель переключения языков и поля перевода:

```vue
<LocaleEditorBar v-model="translations.locale" ... />
<ContentTranslationFields v-else :translations="translations" />
```

Composable `useContentTranslations(entity)` отдаёт прокси `fields`. На языке по умолчанию он читает и пишет саму сущность, на остальных работает с картой переводов. Форма при этом остаётся одна.

</Step>
</Steps>

<Callout type="error" title="Спред убивает переводы">
Интерсептор находит переводимые объекты по `node.constructor`. Разложенная сущность превращается в обычный объект и теряет класс:

```ts
return { ...product, extra: 1 }   // переводы не подставятся
return Object.assign(product, { extra: 1 })  // всё на месте
```

На эти грабли уже наступали: в нескольких сервисах пришлось менять спред на `Object.assign`.
</Callout>

### Удаление

`EntitySubscriber` слушает `afterRemove` и подчищает переводы удалённой записи. Ручных вызовов не нужно.

## Локаль в PrimeVue

У PrimeVue свой словарь: месяцы, подписи пагинатора, кнопки диалогов. Заполняет его отдельный плагин из тех же ключей. Сам список ключей лежит в `unicore-common/locales`, чтобы фронт и словарь нельзя было рассинхронизировать.

Ключи доступности (`aria`) вынесены отдельным списком: они уходят во вложенный объект `locale.aria`, а не в корень словаря.
