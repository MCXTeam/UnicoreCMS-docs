Провайдеры и курсы настраиваются в панели на странице `/payment-settings`.
Для просмотра нужно `panel.config.read`, для изменения `panel.config.update`.
Страница `/payment` управляет бонусами за пополнение.

## Подключение

1. Выберите источник курсов. Баланс CMS ведётся в RUB; валюта счёта задаётся у провайдера.
2. Заполните идентификаторы и ключи из кабинета площадки, укажите валюту и включите метод.
3. В кабинете площадки укажите адрес уведомлений, показанный в панели CMS.
   `API_BASEURL` должен содержать публичный HTTPS-адрес API.
4. Проверьте создание счёта, оплату и зачисление. Если площадка поддерживает тестовый режим,
   сначала проверьте его, затем рабочий магазин.

Настройки применяются без перезапуска. До первого сохранения провайдера используются
переменные его окружения, например `FREEKASSA_ENABLED`, `FREEKASSA_MERCHANT_ID`,
`FREEKASSA_SECRET_KEY` и `FREEKASSA_SECRET_KEY_SECOND`. После сохранения значения в базе
имеют приоритет над `.env`.

У старых переменных UnitPay, FreeKassa, EnotIO, PayOk, AnyPay и CentApp сохраняется
проверка обязательных ключей при старте CMS. Если подключаете их через панель,
оставьте `*_ENABLED` в окружении выключенным. При включённом флаге заполните в `.env`
весь обязательный набор, даже если настройки уже сохранены в базе.

Ключи в ответах API скрыты: панель показывает только признак наличия. Пустое поле ключа
при сохранении оставляет прежнее значение. API поддерживает явное удаление через
`clearSecrets`. Настройки хранятся зашифрованными в `unicore_payment_settings`;
команда `crypto-rewrap` учитывает эту таблицу при смене ключа шифрования.

## Поддерживаемые провайдеры

| Провайдер | ID | Что нужно учесть |
| --- | --- | --- |
| Platega | `platega` | Merchant ID, Secret и валюта счёта |
| CrystalPay | `crystalpay` | Логин кассы, API Secret и Salt |
| ЮKassa | `yookassa` | Shop ID, секретный ключ, валюта и тестовый режим |
| Heleket | `heleket` | Merchant ID, Payment API Key и валюта аккаунта |
| Tebex | `tebex` | Режим Checkout или Headless, приватный ключ и Webhook Secret |
| CloudPayments | `cloudpayments` | Public ID, API Secret, валюта и тестовый режим |
| Lava Business | `lava` | Shop ID, Secret Key и Additional Key для lava.ru Business |
| WebMoney | `webmoney` | Кошелёк, Secret Key Merchant, SHA256; валюта соответствует типу кошелька |
| ЮMoney | `yoomoney` | Номер кошелька, секрет HTTP-уведомлений; только RUB |
| FreeKassa | `freekassa` | Merchant ID, оба секретных слова и валюта |
| AnyPay | `anypay` | Merchant ID и секретный ключ; только RUB |
| CentApp | `centapp` | Shop ID и токен; только RUB |
| EnotIO | `enotio` | Merchant ID и два секретных ключа; только RUB |
| PayOk | `payok` | Shop ID и секретный ключ; только RUB |
| UnitPay | `unitpay` | Public Key и Secret Key; только RUB |

Для WebMoney поддерживаются кошельки Z/E/R/U/K/B. Тип кошелька должен совпадать с выбранной
валютой. Дополнительный ключ подписи платёжной формы необязателен. Валюта Lava Business
должна соответствовать договору магазина: CMS не передаёт её отдельным полем API.

### Tebex

В режиме Checkout API нужны Project ID и доступ к Checkout API от Tebex.
CMS создаёт товар с суммой пополнения.

В режиме Headless API нужны Public Token и Category ID. Приватный ключ должен иметь
доступ к динамическим пакетам в выделенной категории магазина. Если магазин требует
внешней авторизации игрока, сначала выполняется вход на Tebex, затем пользователь
возвращается к продолжению корзины. Проверьте этот сценарий на своём типе магазина.

Для обоих режимов настройте webhook `payment.completed`. CMS также отвечает на
`validation.webhook`. Налоги и комиссии не входят в сумму пополнения: сверяется цена
единственного товара. Корзины с купонами или подарочными картами автоматически не
подтверждаются. Валюта настроек CMS должна совпадать с валютой магазина Tebex.

### Чеки

В ЮKassa и CloudPayments есть переключатель передачи данных чека. Перед включением
задайте налоговую ставку, предмет и способ расчёта в обозначениях API провайдера.
При необходимости заполните систему налогообложения. CMS не подставляет эти значения
автоматически. В чек передаётся email пользователя и одна позиция пополнения.

## Курсы валют

Ручной курс задаётся в RUB за единицу валюты. При USD = 90 пополнение на 900 RUB создаёт
счёт на 10 USD. Сумма счёта округляется вверх до двух десятичных знаков.

Режим ЦБ РФ загружает таблицу курсов и учитывает номинал валюты. В панели показывается
дата самой таблицы; она может относиться к предыдущему рабочему дню. Кэш используется
один час и обновляется при создании валютного счёта или кнопкой в панели. Если ЦБ
недоступен, допускается сохранённый снимок не старше семи суток. Без пригодного курса
создать валютный счёт нельзя.

У каждого платежа сохраняются исходная сумма в RUB, сумма и валюта счёта, курс и дата.
Изменение настроек не пересчитывает существующие счета. При подтверждении CMS сверяет
уведомление с сохранёнными суммой и валютой, затем зачисляет исходную сумму с бонусом.

## Подтверждение оплаты

Адрес уведомлений имеет вид `https://api.example.com/payment/methods/<id>/handler`.
Способ проверки зависит от провайдера: подпись, заголовки авторизации, IP отправителя
или повторный запрос статуса через API. Подробности находятся в
[контракте платежей и вебхуков](/docs/api/payments).

Возврат покупателя по адресу `/payment/redirect/success/<id>` сам по себе не подтверждает
оплату. Даже если игрок закрыл вкладку, корректное уведомление зачислит деньги.

<Callout type="warn" title="Проверяйте адрес API и прокси">
Уведомления должны приходить на публичный API. Если сервер стоит за nginx, настройте
`TRUST_PROXY`, чтобы проверки IP видели адрес отправителя. Для FreeKassa успешный ответ
обработчика имеет вид `YES`; остальные площадки используют свой формат ответа.
</Callout>

## Бонусы за пополнение

**E-Commerce → Пополнение.** Таблица порогов: пополнил на столько-то, получил процент сверху.

| Сумма | Бонус к пополнению, % |
| --- | --- |
| 500 | 5 |
| 1000 | 10 |
| 3000 | 15 |

Работает ступеньками: сервер берёт самый высокий порог, который платёж перешагнул, и считает процент от всей суммы платежа. При такой таблице пополнение на 1200 зачислит 1320.

Бонус приходит в ту же реальную валюту, а не в бонусную. Каждому порогу можно задать иконку, тогда на странице пополнения они показываются списком наград.

Если порогов нет, игрок получает ровно сумму платежа.

## Жизненный цикл платежа

Счёт создаётся, когда игрок нажимает «Пополнить», и остаётся в базе, даже если вкладку закрыли. Брошенные счета копятся быстро, поэтому в настройках есть автоочистка: ставьте 7–14 дней.

Оплаченные платежи лучше хранить дольше: именно к ним приходят с «я платил, где деньги». В карточке платежа видно сумму, метод, ID счёта у агрегатора и IP, с которого пришло уведомление.
