Донат в UnicoreCMS складывается из двух разных вещей, которые часто путают.

Донат-группа — привилегия целиком: VIP, Premium, Deluxe. У неё есть игровой идентификатор, на сервере её выдаёт плагин прав, и за ней обычно тянется целый список возможностей.

Донат-право — одна возможность в розницу: полёт, набор `/kit weekly`, цветной ник. Берут те, кому не нужен весь пакет.

## Периоды

Период задаёт, на какой срок покупается привилегия. Заводить периоды надо раньше групп.

| Поле | Что это |
| --- | --- |
| Название | «Месяц», «Навсегда» |
| Время в секундах | Ноль означает бессрочно |
| Множитель цены | На сколько умножается базовая цена |

Итоговую цену определяет множитель. Базовая цена группы это цена за один период: месяц идёт с множителем 1, три месяца с 2.7 (то есть со скидкой), навсегда с 10.

Периоды общие для всех групп и прав, но каждая группа выбирает свой набор. «Навсегда» нужно не везде.

## Донат-группа

**E-Commerce → Донат → Донат-группы → Создать.**

| Поле | Зачем |
| --- | --- |
| Название, описание, иконка | Витрина |
| ID в игре | Имя группы в LuckPerms или другом плагине прав |
| Цена, скидка, свой процент оплаты бонусами | Деньги |
| Продаётся | Можно ли купить привилегию; выключите для ручной выдачи сотрудникам |
| Приоритет | Порядок на странице доната |
| Серверы | Где привилегия действует |
| Доступные периоды | Какие сроки можно купить |
| Инжект веб-прав | Что открывается на сайте |
| Веб-роль на время привилегии | Какую роль сайта получает владелец до окончания срока |
| Возможности (построение блока) | Список «что входит» для витрины |
| Киты | Наборы, которые привилегия даёт в игре |
| Служебная роль у связанной роли сайта | Включает владельцев привилегии в состав команды на своём сервере |
| Цвет роли | Каким цветом название выводится в составе команды |

ID в игре должен совпадать с именем группы на сервере. Если в LuckPerms группа называется `vip`, то и здесь пишите `vip`, иначе игрок ничего не получит.

Возможности идут галочками на карточке привилегии: «Приватные регионы ×5», «Доступ к /fly», «Цветной ник». На логику они не влияют, зато по ним игрок и выбирает.

<Callout type="warn" title="В инжект веб-прав идут только `player.`">
В инжект можно положить только права из ветки `player.`, форма проверяет это при сохранении. Связанная веб-роль проверяется отдельно: роль с административными или служебными правами нельзя получить покупкой, подарком или подарочным кодом.
</Callout>

## Донат-право

Три типа, и они ведут себя по-разному:

| Тип | Что делает |
| --- | --- |
| Игровое | Выдаёт узел прав на сервере, например `essentials.fly` |
| Веб | Открывает возможность на сайте, из ветки `player.` |
| Кит | Даёт набор предметов |

Права тоже покупаются на период и снимаются, когда срок вышел.

## Выдача сотрудникам без продажи

В карточке группы или права откройте раздел с ценой и выключите **Продаётся**. Цена перестанет быть обязательной, запись исчезнет из публичного каталога. Покупка по прямому запросу, подарок, передача действующей привилегии и активация подарочного кода тоже будут запрещены.

Выдайте привилегию из вкладки **E-Commerce** в [карточке пользователя](/docs/admin/users). Там же её можно снять. Для выдачи нужны права на донат соответствующего сервера; если привилегия связана с веб-ролью, действуют и ограничения выдачи этой роли. Статус «Продаётся» защищён тем же правом на поле, что и цена.

Например, создайте группу `moderator` с игровым ID `moderator`, выберите сервер и роль сайта «Модератор», затем выключите продажу. Административная выдача назначит игровую группу на выбранном сервере и веб-роль на тот же срок. Одна только роль сайта игровую группу не выдаёт.

## Веб-роль на время привилегии

Связанная роль действует, пока есть хотя бы одна активная группа или право с этой ролью. Если снять одну из двух таких привилегий, роль останется до снятия или истечения второй. Ручное назначение роли также сохраняется после окончания доната.

Изменение или очистка поля **Веб-роль на время привилегии** пересчитывает роли уже действующих владельцев. Сохранение цены или другого несвязанного поля сохраняет выбранную роль.

Администратор может назначить связанную роль только в пределах своих полномочий и её приоритета. Для роли с правами панели дополнительно нужно `panel.users.grant.panel`; нужные права должны быть и у выдающего. Эти проверки работают при настройке связи, выдаче и снятии привилегии.

## Киты привилегий

Это не те же киты, что в магазине. Кит привилегии игрок получает вместе с группой: например, стартовый комплект для VIP. Собирают его отдельно, а привязывают к группе или к отдельному праву.

## Что происходит после покупки

1. С баланса списывается цена периода.
2. Игроку записывается группа или право со сроком.
3. Веб-права начинают действовать на сайте сразу.
4. Игровая часть уезжает на сервер плагином или [через RCON](/docs/admin/issuance).

На сайте истёкшие веб-права и связанные роли перестают учитываться при следующей проверке пользователя, без ожидания фоновой очистки. Раз в десять минут задача удаляет истёкшие выдачи и отправляет снятие игровой части на сервер.

<Callout title="Продление накапливается">
Если игрок покупает ту же группу второй раз до окончания срока, время прибавляется к оставшемуся. Если срок уже истёк, новый отсчитывается от текущего времени. В командах RCON за накопление отвечает флаг `accumulate` в шаблонах LuckPerms.
</Callout>

## Страницы привилегий

У каждой группы автоматически появляется своя страница на сайте с описанием, особенностями, выбором периода и сервера. Верстать ничего не надо, а вот описание и особенности заполните: пустая страница продаёт плохо.

Всё это [переводится](/docs/admin/locales), включая заголовки и тексты особенностей.
