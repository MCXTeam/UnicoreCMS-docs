title: Модуль «Команда проекта»
description: Страница состава, которая собирается из служебных ролей и привилегий
---

Модуль добавляет на сайт страницу `/mod/team` со списком тех, кто ведёт проект: администрация, модераторы, хелперы. Состав не заводится руками — он берётся из того, что уже есть в панели.

## Откуда берутся люди

Состав определяется ролями сайта с включённым флажком **Служебная роль**:

| Источник | Где отметить | Куда попадает человек |
| --- | --- | --- |
| Ручная роль сайта | Назначить служебную роль в карточке пользователя | В общий раздел, поскольку у ручной роли нет сервера |
| Донат-группа или игровое донат-право | Выбрать служебную роль в поле «Веб-роль на время привилегии» и выдать привилегию | В раздел сервера выдачи |
| Веб-право без сервера | Выбрать служебную роль в поле «Веб-роль на время привилегии» и выдать право | В общий раздел |

Пока привилегия активна, человек виден в соответствующем разделе. После её снятия или истечения срока источник исчезает. Другая действующая привилегия или ручная роль могут сохранить человека в составе. Один человек может находиться в нескольких разделах.

Ручное назначение роли «Модератор» на сайте само по себе не выдаёт игровую группу и не выбирает сервер. Для такой выдачи создайте [служебную привилегию без продажи](/docs/admin/donate#выдача-сотрудникам-без-продажи).

Подпись под ником — это название роли или привилегии, а её цвет задаётся там же, где и сам флажок.

## Что настраивается в модуле

**Расширения → Команда проекта.** Здесь редактируются описание участника, категории и его размещение в разделах. Описание переводится на другие языки как обычный контент.

Заголовок страницы, подзаголовок и название общего раздела лежат в настройках модуля на странице «Модули».

Режим отображения выбирается там же:

| Режим | Как группируются участники |
| --- | --- |
| По серверам | Общий раздел и серверы, на которых выданы привилегии |
| По категориям | Категории, назначенные в редакторе состава |
| Всё вместе | Один список без разделов |

Включение **На всех серверах** в настройках участника добавляет его в общий раздел. Оно меняет только размещение на странице команды и не выдаёт игровые группы или права на серверы. Участник с ручной служебной ролью уже попадает в общий раздел автоматически.

В блоке **Порядок в разделах** меньшее число ставит участника выше; **Авто** использует приоритет и имя. В `team` 1.2.1 ручной порядок общего раздела работает и в режиме по серверам, и в режиме по категориям. Режим «Всё вместе» использует автоматический порядок.

## Установка

Модуль живёт в отдельном репозитории [UnicoreCMS-modules](https://github.com/MCXTeam/UnicoreCMS-modules/tree/main/team) и лежит там исходниками. Как собрать серверную часть, написано в README репозитория: клоны кладутся рядом, потому что контракт `unicore-api` в npm не публикуется.

```bash
pnpm --filter unicore-module-team run build
```

Дальше как с любым модулем: соберите архив из `module.json`, `package.json`, `server`, `client`, `admin`, `locales`, поставьте его через панель, включите и пересоберите фронты. Подробности — в [Установке](/docs/extensions/install).

## Что внутри — для разработчика

Модуль интересен как пример: почти всё он берёт у ядра и почти ничего не хранит.

- состав приходит из фасада `core().staff.members()` — ядро само сводит роли сайта и выданные привилегии;
- названия и иконки разделов — из `core().servers.all()`;
- `mod_team_notes` хранит описания, `mod_team_categories` категории, `mod_team_member_categories` размещение участников и порядок;
- описание переводится через `@Translatable('mod.team.note', ['text'])`, редактор в панели подключается одной строкой.

См. [Контракт для модулей](/docs/extensions/api).
