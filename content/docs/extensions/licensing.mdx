Эта функция добавлена в ветку разработки вместе с API 1.16.0. Она ещё не входит в опубликованный релиз CMS 1.3.2.

## Активация

Откройте **Утилиты → Лицензии**. Для просмотра нужно право `panel.extensions.read`, для активации, обновления разрешения и переноса — `panel.extensions.manage`.

Укажите ключ и данные релиза, полученные при покупке. Одна лицензия действует на одну установку CMS на одном сервере. API, сайт, админка и штатные фоновые процессы этой установки используют общий координатор лицензий.

При каждом новом запуске платному расширению нужна связь с сервером лицензий. Уже работающая установка продолжает работу при потере связи до истечения подписанного разрешения, максимум 30 минут. Перезапуск не продлевает этот срок и требует новой онлайн-проверки.

Отказ блокирует соответствующий модуль или тему. Ядро CMS и другие расширения продолжают работать. Платная тема использует базовое оформление при отказе в лицензии; уже полученные браузером JS и CSS невозможно отозвать.

## Покупка и обновления

Право использовать релиз и право получать новые версии учитываются отдельно. Разовая покупка может сохранять доступ к купленным версиям после окончания периода обновлений. У подписки срок использования определяется её условиями. Для разовой покупки дополнительных обновлений расширяется доступный набор релизов.

Это проверки прав доступа. Магазин, приём оплаты и автоматическое выставление лицензий подключаются отдельно.

## Перенос

На прежней установке нажмите **Перенести** и укажите адрес новой CMS. Сохраните одноразовый код: он показывается в текущем окне и не сохраняется в браузере.

На новой установке выберите активацию по коду переноса. Разрешение начнёт действовать после истечения разрешения прежнего сервера, максимум через 30 минут. При завершении переноса выдаётся новый ключ; прежний ключ больше не используется.

Если прежний сервер утрачен, перенос выполняет поддержка. Восстанавливать резервную копию установки на втором работающем сервере нельзя: это создаёт две конкурирующие сессии.

Неудачная попытка второй активации сама по себе не отзывает ключ. Если сервис подтверждает продолжительную одновременную работу двух установок, ключ отзывается окончательно. Дальнейшее решение принимает поддержка.

## Разработчикам

Платный модуль объявляет контракт в `module.json`:

```json
{
  "unicoreApi": "^1.16.0",
  "commercial": {
    "productId": "vendor.product",
    "protocol": 1,
    "runtime": "encrypted-v1",
    "frontend": "browser"
  }
}
```

`productId` должен быть зарегистрирован у издателя. Одного поля в манифесте недостаточно для создания продаваемого продукта. Пакет также содержит подписанный манифест артефакта; установка и загрузчик проверяют его содержимое и связь с релизом.

Серверная сборка `encrypted-v1` хранится зашифрованной. Сервис выдаёт ключ только авторизованному запущенному процессу; загрузчик расшифровывает код в памяти. В архив не включаются открытые серверные исходники, дополнительные незашифрованные серверные чанки и source maps. Ключи подписи издателя и сервера лицензий покупателям не передаются.

В серверном коде доступны `assertModuleLicense`, `requireModuleLicense` и декоратор `LicensedModule` из `unicore-api/server`. Проверки закрывают вызовы сервисов после отзыва и окончания разрешения. Декоратор сохраняет метаданные Nest и TypeORM; методы завершения работы продолжают вызываться для очистки ресурсов.

Платные Nuxt-слои модулей исполняются только в браузере: `commercial.frontend` должен быть `browser`. Серверные плагины и `.server.*` файлы в таком слое запрещены. Серверную логику размещайте в защищённом backend модуля. Для платных SSR-тем используется отдельная схема запуска с базовой темой для переключения при отказе.

Обфускация затрудняет правку проверок, а шифрование закрывает запуск оригинальной серверной сборки без выданного ключа. Владелец машины с root-доступом после законной расшифровки может извлечь код из памяти. Полной защиты от этого у поставляемого на его сервер кода нет; критичную логику, которую нельзя раскрывать, нужно исполнять на сервере издателя.
