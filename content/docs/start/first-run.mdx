<Steps>
<Step>

### Создать администратора

Регистрация через сайт даёт обычного игрока. Первый суперпользователь создаётся из консоли:

```bash
pnpm --filter unicore-server exec node dist/cli/main.js user-create Admin admin@example.com пароль true
```

Аргументы по порядку: ник, почта, пароль, суперпользователь. Последний `true` обязателен. Без него получится обычный аккаунт, который в админку не пустят.

В Docker то же самое:

```bash
docker compose exec app pnpm --filter unicore-server exec node dist/cli/main.js user-create Admin admin@example.com пароль true
```

<Callout title="Суперпользователь">
У него есть все права, всегда, независимо от ролей. Держите его как аварийный доступ, а работать команде давайте через [роли](/docs/admin/roles).
</Callout>

</Step>

<Step>

### Зайти в админку

Откройте `ADMIN_BASEURL` (по умолчанию это сайт на порту 4000) и войдите созданной учёткой. Сайт работает, а страница логина не открывается? Почти наверняка виноват CORS. Сервер разрешает только `BASEURL` и `ADMIN_BASEURL`, так что проверьте, что адрес админки записан там ровно так, как вы его открываете, вместе со схемой и портом.

</Step>

<Step>

### Добавить сервер

**Управление контентом → Серверы → Создать.** Минимум, который нужен:

- **ID**: короткий латинский идентификатор, например `hitech`. Он попадёт в URL и в API, менять его потом больно.
- **Название** и **версия**: их увидит игрок.
- **Мониторинг**: адрес и порт для Query, тогда на сайте покажется онлайн.
- **Способ выдачи**: плагин или RCON, см. [Выдача покупок](/docs/admin/issuance).

Товары привязываются к серверам, поэтому без единого сервера магазин и донат работать не будут.

</Step>

<Step>

### Пройтись по настройкам сайта

**Основное → Настройки.** Там живут ссылки на соцсети, курс обмена валют, цена разбана, реферальные награды и переключатели вроде обязательной активации почты. Всё это разбирается [здесь](/docs/admin/settings).

</Step>

<Step>

### Проверить почту

**Управление контентом → Email-сообщения → Тестировать.** Если письмо не пришло, регистрация будет молча ломаться: игрок зарегистрируется, но активировать аккаунт не сможет.

</Step>
</Steps>

## Что уже создано само

При первом старте сервер сам заводит два языка (русский и английский) и заливает в базу все ключи интерфейса. Дальше их правят прямо в админке, см. [Языки и переводы](/docs/admin/locales).

Команда `pnpm run seed` добавляет ещё две роли: `admin` с правами `admin.*` и `editor` с правами `editor.*`. Их удобно взять за основу и не выдавать людям суперпользователя.

<Callout type="warn" title="Сид тянет за собой демо-данные">
`seed` заодно создаёт демонстрационные серверы, товары и новости, а при `DEV_SEED=1` ещё и 250 фейковых игроков. На чистом продакшене роли проще создать руками в разделе **Роли**.
</Callout>
