У сервера UnicoreCMS обычный REST-API на NestJS. Сайт и админка ходят в него теми же запросами, что доступны вашему коду; приватных каналов между фронтом и бэкендом нет.

## Базовый адрес

```
https://api.example.com
```

Этот адрес лежит в `.env` как `API_BASEURL`. Корень (`/`) редиректит на сайт, чтобы в API случайно не заходили браузером.

Форматы: JSON на вход и на выход, а файлы загружайте как `multipart/form-data`.

## Заголовки

| Заголовок | Зачем |
| --- | --- |
| `Authorization: Bearer <token>` | Авторизация пользователя |
| `Authorization: Api-Key <secret>` | Авторизация машинного клиента |
| `x-locale: en` | Язык переводимого контента в ответе |
| `x-raw-content: 1` | Отдать оригиналы вместо переводов |
| `Timezone: Europe/Moscow` | Таймзона клиента |
| `recaptcha: <token>` | Токен reCAPTCHA, если она включена |

<Callout title="`x-locale` и `x-raw-content`">
Первый переводит поля контента на лету: названия товаров, описания серверов, тексты новостей. Второй выключает подмену, и редактор правит оригинал, а не перевод. Без этих заголовков контент придёт на языке по умолчанию.
</Callout>

## Коды ответов

| Код | Что означает |
| --- | --- |
| `200`, `201` | Всё хорошо |
| `400` | Валидация не прошла, в теле список проблем по полям |
| `401` | Нет токена или он протух |
| `403` | Токен есть, прав не хватает |
| `404` | Записи нет |
| `429` | Слишком часто |
| `500` | Что-то сломалось на сервере |

Тело ошибки — стандартное для Nest:

```json
{
  "statusCode": 400,
  "message": ["username must be a valid username"],
  "error": "Bad Request"
}
```

<Callout type="warn" title="Лишние поля вырезаются молча">
У валидации включён `whitelist: true`, поэтому поля, которых нет в DTO, пропадают из запроса без ошибки. Если что-то «не сохраняется», первым делом проверьте, что имя поля точно совпадает.
</Callout>

## Ограничение частоты

Лимиты стоят там, где опасен перебор: на всей ветке `/auth/*` и на активации подарочных кодов.

Базовый лимит — 10 запросов за 2 минуты с адреса. На отдельных ручках жёстче:

| Ручка | Лимит |
| --- | --- |
| Регистрация | 5 в час |
| Подтверждение почты | 10 за 10 минут |
| Повторная отправка кода | 3 за 10 минут |
| Сброс пароля | 5 в час |

Машинные клиенты (плагин, лаунчер, дашборд) под лимиты не попадают: проверка смотрит на права группы `kernel`. На ветку `/auth/*` это послабление не распространяется — вход, регистрация и сброс пароля считаются по лимиту для всех, включая суперпользователя, иначе угнанный админский токен снимал бы защиту от перебора.

Вдобавок к лимиту по адресу вход считает неудачные попытки по паре «аккаунт + адрес» в окне 15 минут. После десятой неудачи включается пауза, которая удваивается с каждой следующей попытки и упирается в пять минут. Если задан `RECAPTCHA_SECRET`, порог поднимается до 25 попыток, зато с четвёртой неудачи вход начинает требовать капчу.

Аккаунт при этом не блокируется: в ключе счётчика есть адрес, поэтому перебор с чужой машины тормозит перебирающего, а владелец продолжает заходить со своего адреса. Удачный вход обнуляет счётчик.

<Callout type="error" title="Лимиты считаются по IP">
А IP сервер берёт с учётом переменной `TRUST_PROXY`. Если её не настроить, все запросы придут как будто с одного адреса, и лимит выключит сайт сразу для всех.
</Callout>

## Пагинация

Списочные ручки принимают страницу, размер страницы, сортировку, поиск и фильтры:

```http
GET /store/products?page=1&limit=20&sortBy=price:DESC&search=меч
```

Ответ:

```json
{
  "data": [],
  "meta": { "itemsPerPage": 20, "totalItems": 143, "currentPage": 1, "totalPages": 8 },
  "links": {}
}
```

Фильтр записывается как `filter[колонка]=$оператор:значение`, операторов шесть: `$eq`, `$gt`, `$gte`, `$lt`, `$lte` и `$btw` (последний берёт две границы через запятую).

```http
GET /store/products?filter[price]=$btw:100,500
```

Сортировка, поиск и фильтры работают только по колонкам, которые ручка разрешила явно. Всё остальное молча игнорируется — запрос вернёт список без ошибки, просто без вашего условия. Если фильтр «не применился», дело почти всегда в этом.

## Что открыто без авторизации

Публичные ручки отдают то, что и так видит на сайте гость:

| Метод | Путь | Что отдаёт |
| --- | --- | --- |
| `GET` | `/config/public` | Публичные настройки сайта |
| `GET` | `/servers` · `/servers/:id` | Серверы |
| `GET` | `/servers/online` | Текущий онлайн |
| `GET` | `/news` · `/news/:id` | Новости |
| `GET` | `/pages` · `/pages/:id` · `/pages/rules` | Статические страницы |
| `GET` | `/donates/groups/server/:id` | Привилегии сервера |
| `GET` | `/locales` · `/locales/:code/messages` | Языки и словарь интерфейса |
| `GET` | `/players/banlist` | Баны |
| `GET` | `/players/playtime` | Топ по времени в игре |
| `GET` | `/players/votes-list` | Топ голосующих |
| `GET` | `/users/public/username/:username` | Публичный профиль |
| `POST` | `/auth/login` · `/auth/register` · `/auth/refresh` | Вход и регистрация |

Всё остальное требует токена.

<Callout title="Каталог магазина закрыт для гостей">
Витрина живёт на ручках `/store/products/protected/*`, и без входа они не работают: цены и доступность зависят от прав игрока и его серверов. Особых прав не нужно, достаточно войти в аккаунт.
</Callout>

## Swagger

Вне production на `/docs` поднимается Swagger со всеми ручками. На боевом его выключили намеренно, чтобы не публиковать карту API вместе с админскими методами.

Чтобы посмотреть локально:

```bash
pnpm --filter unicore-server run dev
# http://127.0.0.1:5000/docs
```
