## Создание счёта

Вошедший игрок с правом `player.payment` вызывает метод выбранного провайдера:

```http
POST /payment/methods/unitpay/link
Authorization: Bearer <accessToken>
Content-Type: application/json

{ "amount": 500 }
```

`amount` задаёт сумму пополнения баланса в RUB, независимо от валюты площадки. Сервер
читает сохранённые настройки провайдера, проверяет обязательные поля и рассчитывает
сумму счёта. При отсутствии пригодного курса или конфигурации создание отклоняется.

Ответ содержит ссылку для перехода к оплате:

```json
{ "link": "https://payment.example/checkout" }
```

Для провайдеров с HTML-формой ссылка ведёт на публичный маршрут CMS
`GET /payment/methods/<id>/checkout/:token`, который отправляет форму на площадку.
Продолжение авторизации корзины Tebex проходит через `GET /payment/methods/tebex/resume/:token`.
Клиенту достаточно открыть полученную ссылку; собирать форму или корзину самому не нужно.

Поддерживаемые ID и особенности площадок перечислены в
[настройках платёжных систем](/docs/admin/payments).

## Подтверждение оплаты

Провайдер отправляет уведомление на свой обработчик:

```http
POST /payment/methods/<id>/handler
```

Это публичный маршрут без пользовательского Bearer-токена. Подлинность уведомления
проверяется по протоколу площадки. Проверка IP нужна тем провайдерам, которые её
используют; единого списка IP и единого формата подписи для всех методов нет.

| Провайдеры | Проверка |
| --- | --- |
| Platega | Заголовки авторизации и запрос статуса |
| CrystalPay, Heleket | Подпись и запрос состояния счёта |
| ЮKassa | Запрос API; принимается `succeeded` с `paid=true` |
| CloudPayments | Подпись; завершённая операция Payment |
| Tebex | Подпись webhook и событие `payment.completed` |
| ЮMoney | HMAC-SHA256 `sign`, сумма из `withdraw_amount` |
| WebMoney | Подпись Merchant с SHA256 |
| FreeKassa | IP отправителя и второе секретное слово |

После проверки CMS находит сохранённый счёт и сверяет сумму и валюту. Баланс получает
исходную сумму в RUB с бонусом пополнения. Неверная подпись, неподходящий статус, чужая
валюта или другая сумма не подтверждают платёж.

<Callout title="Повторное уведомление">
Зачисление выполняется условно, только для ожидающего счёта. Параллельные повторные
уведомления не пополняют баланс повторно.
</Callout>

Формат ответа зависит от площадки. Например, FreeKassa ожидает `YES`; нельзя требовать
общего `OK` от всех обработчиков. Возврат пользователя через
`/payment/redirect/success/<id>` или `/payment/redirect/fail/<id>` только меняет страницу
в браузере и не зачисляет деньги.

## Настройки через API

Все маршруты ниже требуют авторизации. Чтение закрыто правом `panel.config.read`,
изменение и обновление курсов правом `panel.config.update`.

| Метод | Маршрут | Действие |
| --- | --- | --- |
| GET | `/admin/payment-settings` | Провайдеры, схема полей, настройки курсов и снимок ЦБ |
| PATCH | `/admin/payment-settings/:id` | Настройки провайдера |
| PATCH | `/admin/payment-settings/rates` | Источник и ручные курсы |
| POST | `/admin/payment-settings/rates/refresh` | Обновление снимка ЦБ |

Тело обновления провайдера содержит `enabled: boolean`, `values: Record<string, string>`
и необязательный `clearSecrets: string[]`. Имена полей и доступные варианты возвращает
GET в схеме конкретной площадки. Включение провайдера проверяет обязательные поля.

GET не возвращает секреты: вместо них приходят пустые строки и признаки `configured`.
Пустая строка при обновлении сохраняет прежний ключ; для удаления укажите имя поля
в `clearSecrets`. В журнал записываются имена изменённых полей без их значений.

Пример настройки ручных курсов:

```json
{
  "mode": "manual",
  "baseCurrency": "RUB",
  "manualRates": { "RUB": 1, "USD": 90, "EUR": 100 }
}
```

Режим может быть `manual` или `cbr`; базовая валюта CMS остаётся RUB. Курсы задаются
в RUB за единицу валюты. Снимок ЦБ содержит дату таблицы, время загрузки и курсы.
Сохранённая котировка уже созданного счёта не меняется при обновлении этих настроек.

## Отладка

- Сверьте публичный HTTPS-адрес `API_BASEURL` и адрес обработчика в кабинете площадки.
- При ошибке проверки IP настройте `TRUST_PROXY` и проверьте адрес отправителя за прокси.
- При ошибке подписи сверяйте ключи с настройками в панели: после сохранения они имеют
  приоритет над окружением. У FreeKassa и EnotIO ключи для ссылки и уведомления различаются.
- Если сумма или валюта не совпали, проверяйте сохранённый счёт, настройки магазина
  площадки и курс на момент создания. Изменение общего курса старый счёт не исправляет.
- В Tebex проверьте единственный товар, валюту магазина и отсутствие купонов и подарочных карт.
- Реальные оплаты проверяйте отдельно: локальные тесты подписей и валют не подтверждают
  подключение конкретного магазина.
